### 2. Orchestration

> 추론 엔진을 언제&어떻게 사용할 지 결정하는 제어하는 파트 
목표 설정 + 기억 + 판단
> 

#### 2-1. Profile, goals & instructions

- Agent가 어떠한 목표를 갖는지 정의하는 부분 (시스템 프롬프트)
- *ex) “너는 PCB 불량 원인을 진단하는 agent 다. 이미지가 들어오면 vision 결과와 공정 데이터를 함께 확인 후  원인을 리포트 해라”*

#### 2-2. Memory (short-term / long-term)

- short-term : 지금 처리 중인 대화의 대화 및 중간 결과 기록
- long-term : 과거 이력 및 유사 사례를 DB에 저장했다가 불러오는 것

#### 2-3. Model based Reasoning/Planning

- 위의 두 정보를 가지고 “Model” 을 호출 해 **다음 행동을 결정하는 부분**
- Agent가 어떻게 생각 하는지
- Detail
    - Agent가 실제로 어떻게 “생각”하는지
    - **ReAct (Reason + Act) - Default**
        - “생각 → 행동 → 관찰” 반복, 스텝마다 판단하며 진행
        - *ex) defect 유형 확인 필요 → vision tool 호출 → 결과 확인 → 공정 데이터 확인 필요 → 다른 tool 호출*
    - **CoT (Chain-of-Thought) - 판단 근거 명확히 하고 싶을 때**
        - 행동(tool) 없이, 문제를 단계별로 쪼갠 후 순차적으로 생각만 정리
        - *ex) 불량률이 오른 이유?*
            1. *최근 공정 변경 확인* 
            2. *시기 비교*
            3. *결론*
            
            *미리 논리를 펼쳐두고 답을 내는 방법*
            
    - **ToT (Tree-of-Thought) - 원인이 여러개인 경우 보조 선택**
        - 여러가지 가능성을 동시에 두고 비교 후 가장 그럴듯한 방법 선택

### 3. Tools

> 실제 행동 수단
> 
- Orchestration이 필요하다고 판단하면 호출하는 **외부 기능**
- ex) API, DB 조회 등
- Detail
    - Extension : API를 표준화된 방식으로 바로 호출
        - *vision defect detection API 그대로 연결*
    - Function : Agent가 직접 실행x, 외부 (클라이언트)에서 실행
        - *실제 raw 이미지 파일 접근 필요 (보안상 agent 직접 접근 불가능, 별도 시스템이 처리해야하는 경우)*
    - Data Store : 문서/DB 검색해서 정보 가져오는 것(RAG)
        - *공정 매뉴얼이나 과거 리포트 검색*
